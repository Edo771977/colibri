Raw per-run engine output for the Qwen3.6 OpenMP-runtime experiment, filtered to
the lines the record rests on. Every run is `misure.ps1` on the same machine, the
same container and the same script-generated prompt, 128 generated tokens with
COLI_TIMERS=1 and the CUDA expert tier active. Each invocation produces two
samples: gpu_1_fredda (first run of the invocation) and gpu_2_calda (second).

Both binaries were built from commit 4bc62322b01cb0dcf33e1938701037858296decc
and kept side by side on disk; the arms were alternated across invocations so a
machine drifting mid-session could not hand the win to whichever ran first.

  baseline arm  qwen36_gcc.exe    make qwen36.exe CUDA_DLL=1 ARCH=native
                                  (ucrt64 gcc 16.2, -static, MinGW libgomp)
  trial arm     qwen36_clang.exe  make qwen36.exe CC=clang CUDA_DLL=1 ARCH=native
                                  (MSYS2 CLANG64 clang 22.1.8, LLVM libomp)

Order in wall-clock time: clang-1 (19:04), gcc-2 (19:16), clang-2 (19:18),
gcc-3 (20:35). The highest single sample of the whole record (21.12) is the
clang arm's SECOND run of an invocation that started after a gcc invocation.

libgomp's price is linear in team size on this host -- region 12.0 / 25.0 / 34.0
/ 53.5 us and barrier 6.5 / 20.0 / 35.5 / 70.5 us at 2 / 4 / 8 / 16 threads,
about 4.4 us per thread. That is a runtime waking its team one thread at a time,
and it is why OMP_WAIT_POLICY=active GOMP_SPINCOUNT=200000 moves neither number:
nothing is sleeping.

--- quality gates on this commit ---

Tiny Qwen3.6-shaped fixture against the torch oracle, both toolchains: 16/16.
ids and last logits byte-identical across QWEN36_SHARED_FUSE=0/1 and
QWEN36_CONV_OMP=0/1 at cache caps 1 and 8.
ASan + UBSan on both tiny fixtures: zero diagnostics.
Clang arm, real 35B container, 200 generated tokens read by hand: coherent
Italian, no degradation toward the end. That run used the CPU expert path
(COLI_CUDA unset), not the CUDA tier.

The two arms are NOT comparable byte for byte: gcc and clang vectorise the
scalar code outside the intrinsic kernels differently, so last-bit equality is
not available across compilers and token-exactness against the oracle is the
gate instead.
