--- reading -------------------------------------------------------------------

  - Run B is the measurement of the merged code: -0.02 ms/token, the
    interval [-0.58, 0.54] covers zero, as does run A's [-0.27, 1.33].
    Run A's first pair (+2.00, OFF 17.20 the fastest OFF of that run) is
    most of its mean; without it the other five average +0.24. Why run A
    is slower than run B in both arms (OFF +0.85, ON +1.40 ms/token) is
    not known (an hour apart, same window, different binaries of the same
    kernel).
  - The two timers the integer dot can reach moved little: shared 3.13 ->
    3.06 and router 0.79 -> 0.78 in run B (3.20 -> 3.17, 0.89 -> 0.87 in
    run A). The shared expert runs between qt_issue and qt_take, while the
    GPU computes the resident experts (sh-ovl and shared time that same
    block, so their near-equality is by construction, not evidence), and
    the CPU then waits for the GPU (wait 0.41-0.56 ms/token across both
    runs, a mean over 40 layers, ~10-14 us a layer). A faster shared
    expert is therefore expected to be absorbed in that wait, not shown
    to be in every layer.
    In both runs the ON arm's wait went up (0.46 -> 0.56, 0.41 -> 0.46)
    and so did take (0.54 -> 0.64, 0.50 -> 0.56): the GPU side changed
    too, which the simple overlap picture does not predict; not explained.
  - The arms do not run the same workload. The router goes through
    matmul_d, so with COLI_DENSE_IDOT=1 its logits change from the first
    token and a top-k pick can flip before the text diverges (position
    308); after that the text differs as well. The ON arm misses 6689
    experts against 6463 (hit 86.2 % vs 86.7 %) and its cpu-miss is
    0.17 (run B) and 0.23 (run A) ms/token higher. Per miss the cost is
    about the same, 3.85/6463 vs 4.02/6689 ms/token (+0.9 %; run A
    +2.2 %): the extra cpu-miss comes from different routing, which the
    variable causes, not from a slower miss kernel (the misses run
    matmul_qe, which the variable does not touch). It is larger than the
    0.03-0.07 the shared expert gained; the measurement cannot separate
    the two further.
  - The T705: the 24 runs read the model from D:\modelli\qwen36_i4_gs64,
    with residency 6812/10240 as in the runs from C: of the 28 September
    record (the [place] line is shown identical within each A/B only;
    neither record quotes it, so placement across the two days is not
    compared). Run B's OFF arm (17.43) is close to the 28 September ON
    arm (17.72, the same configuration read from C:), but different
    sessions and builds, so no disk effect is claimed. The OFF arm's text
    equals the 28 September runs from C:, so what these runs read from D:
    and used gave the same text; with 6812 of 10240 experts resident, the
    experts never read are not checked by this.
