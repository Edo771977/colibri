--- reading -------------------------------------------------------------------

  - Run B is the measurement of the merged code: -0.02 ms/token, the
    interval [-0.58, 0.54] covers zero, as does run A's [-0.27, 1.33].
    Run A's first pair (+2.00, OFF 17.20 the fastest OFF of that run) is
    most of its mean; without it the other five average +0.24. Why run A
    is slower than run B in both arms (OFF +0.85, ON +1.40 ms/token) is
    not known (an hour apart, same window, different binaries of the same
    kernel).
  - The two timers the integer dot can reach moved little: shared 3.13 ->
    3.06 and router 0.79 -> 0.78 in run B (3.20 -> 3.17, 0.89 -> 0.87 in
    run A). The shared expert runs while the GPU computes the resident
    experts (sh-ovl equals shared) and the CPU still waits for the GPU at
    the end (wait 0.46-0.56), so a faster shared expert does not shorten
    the layer anyway.
  - The arms do not run the same workload: the text diverges at position
    308, so from there the routing differs. The ON arm misses 6689
    experts against 6463 (hit 86.2 % vs 86.7 %), and its cpu-miss is
    0.17-0.23 ms/token higher. That is a consequence of the different
    text, not of the kernel (the misses run matmul_qe, which the variable
    does not touch), and it is the same size as what the shared expert
    gained; the measurement cannot separate them further.
  - Not measured: perplexity (PPL=1) with COLI_DENSE_IDOT=1, and CONSIST=1
    on the real model with it (CONSIST is covered on the tiny fixture by
    CI). The variable stays opt-in, so neither is needed for the default.
  - The T705: the 24 runs read the model from D:\modelli\qwen36_i4_gs64,
    with residency and placement identical to the runs from C:. Run B's
    OFF arm (17.43) is close to the 28 September ON arm (17.72, the same
    configuration read from C:), but different sessions and builds, so
    no disk effect is claimed.
