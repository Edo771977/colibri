  constant, not a measurement of routing. tier_warmstart (c/qwen36.c:3847)
  runs

      #pragma omp parallel for schedule(dynamic, 16)
      for (int gi = 0; gi < cap_total; gi++) { ... expert_get(m, l, eidw, &e); }

  over cap_total = n_layers * n_experts, under its own comment "Load ALL
  experts into RAM, not just the planned (VRAM) set", BEFORE a single token is
  generated. So miss reaches exactly the expert count on ANY warmstarted run
  of this model at this cap, identical for every prompt, arm and placement.
  The sibling record had already written this -- "the 10240 misses are the
  cold first touch of each expert and are identical by construction" -- and
  the withdrawal quoted that phrase while using the same number as if it
  measured demand. It says nothing about what the prompt routes to.

  Found by review, 22 September 2026. The correction is retracted; the

  THE HIT RATE THIS RECORD QUOTES CANNOT SEE THE PLACEMENT, and that half of
  the correction STANDS. The script reads the line `Expert cache hit rate:`,
  which qwen36.c prints from m.hits/m.miss. Those are incremented in
  expert_get() against m->cache[layer] -- the HOST LRU slot cache. They are
  not the tier's VRAM counters. With cap == n_experts the per-layer cache has
  a slot for every expert, so nothing is ever evicted and the rate is pinned
  by construction. (What guarantees cap == n_experts in these runs is that
  the CUDA tier came up at all -- qwen36_tier.c:499 refuses any cap that
  DIFFERS from the expert count, not merely a smaller one, and the script
  treats the tier failing to come up as a hard stop. An explicit -Cap is not
  by itself the guarantee: with RAM_GB set, qwen36.c lowers even an explicit
  cap.) An unchanged 82.6 % here is not evidence about what the GPU did.

  THE METER THAT DOES BEAR ON IT IS NOT IN THIS RECORD. qwen36_tier.c:1073
  counts, per routed expert per token,

      for(int k=0;k<K;k++){ QSlot *s=qs(layer,eids[k]);
          if(s->resident){ ... G.hits[di]++; } else G.miss++; }

  and prints the result as `[qtier] VRAM hit rate` with `LFRU swaps`. THAT is
  the meter which says whether a displaced expert was ever wanted. The
  explicit-COLI_PLACE record captured it and reads 100.0 % with 0 swaps in all
  twelve runs, which is why its version of the claim stands there. This
  script captures neither figure -- see LIMITATIONS -- so this record can
  neither support nor contradict it.

  THE BOUND ON cpu-miss IS WEAKER THAN FIRST WRITTEN, and that correction
  stands too. An earlier version said a mean of 0.00 to two decimals means
  "no individual run carried one either". cpu-miss is a continuous ms/token
  quantity, not a count -- it reads 4.79 and 5.06 in
  qwen36-place-clang-clean-2026-09-20-raw.txt:48 -- so a six-run mean below
  0.005 bounds the six-run sum below 0.03 and therefore each run below 0.03
  ms/token. Small, and not zero.

So what this run establishes about cost is one thing only: displacing 100
experts cost under 0.03 ms/token on the one timer here that watches it. It
does not establish that they were unwanted, and -- contrary to what the first
correction said -- it does not establish the opposite either.

And the cost evidence here is WEAKER than the explicit-COLI_PLACE record's,
not stronger. That record read the per-run values from all twelve logs and
also carried `VRAM hit rate 100.0 %, LFRU swaps 0, in all twelve`. This
script captures neither VRAM hit rate nor LFRU swaps, and reports means rather
than per-run values. The four cost numbers above are byte-for-byte the ones
that record already published; this run does not improve on them.

It is an answer about THIS card, THIS prompt and THIS heat table, and the heat
table was warmed on the prompt that is then measured -- the most favourable
point available for the claim that nothing needed was evicted. On an 8 or 12 GB
card, or with flatter routing, the same 100 experts could be ones the run does
want, and the cost would appear in cpu-miss. qwen36_tier.c:310 says the placer
will take the trunk anyway: without a heat table the marginal expert is worth
2*topk/n_experts per byte (0.06 here) and "the trunk always wins".

--- LIMITATIONS ------------------------------------------------------------

Stated because each one is something a reader could otherwise assume:

  - The commits behind the two binaries are NOT recorded. The script prints 16
    hex of each sha256 and the header gives the build recipe, but nothing in
    the output ties PRE to a specific main commit or POST to a specific branch
    commit. The script should print that; it does not.
  - AND THAT UNDERMINES THE "SAME DLL" CONTROL ABOVE. Reusing one coli_cuda.dll
    removes a confounder only if both binaries were built from commits that
    differ by #39 alone. #39 itself touches no CUDA source -- that part is
    verified -- but with neither commit recorded, "the DLL is the same" cannot
    be checked against "the sources differ by exactly the change under test".
    The two limitations are one limitation.
  - The hit rate this record quotes is the HOST expert cache's, not the tier's
    VRAM hit rate, and the script captures neither the VRAM hit rate nor the
    LFRU swap count that the explicit-COLI_PLACE record carried. The cost
    evidence here is weaker than that record's, not stronger; see the section
    on what the placer decided.
  - attnproj 10 is the MAXIMUM over the six runs of the arm, not a per-run
    figure. What is established per run is that every POST run placed more
    than zero (the warning never fired) and every PRE run placed exactly zero
    (the guard would have thrown).
  - budget, expert count, hit rate and cpu-miss are MEANS over six runs. The
    script does not print them per run, so "identical in every repetition" is
    not established here the way it was in the explicit-COLI_PLACE record,
    where the per-run values were read from all twelve logs.
  - (shared) and (router) are missing for session 1, as described above.
  - The per-phase rows are arm means over six runs; there are no error bars.
  - Nothing here measures prefill. The fused GEMV is mounted only at S == 1.
