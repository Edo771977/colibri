--- reading -----------------------------------------------------------------------

  - The gain is the lever's target: cpu-miss (ms per decode token) falls
    by 2.39, 3.99 -> 1.60, and the misses over the whole run (prompt rows
    and decode steps together) fall by 3943, 6463 -> 2520. moe falls by
    2.07, step() by 2.20; attn, dn and head move by 0.07 or less.
  - Other timers rose; none of the rises is attributed here. The (router)
    timer covers only the gate matmul (c/qwen36.c, tm_add slot 4), which is
    the same work in both arms, yet reads 0.78 -> 0.91; route_select runs
    after it and is timed by no sub-counter, only inside moe, so the
    lever's own ranking cost is not measured separately. The shared expert,
    also the same work in both arms, reads 3.19 -> 3.33. wait 0.39 -> 0.57
    is part of take 0.48 -> 0.67 (the take split), so the two are mostly
    one rise; wait grows both when the GPU computes more experts and when
    the CPU side finishes sooner, and the meters do not separate the two.
  - The rows differ between the arms after the text diverges, so the
    misses compared are not of the same tokens; the meters are of the ON
    arm's own routing.
  - Determinism: with QT_UPLOAD_SYNC=1 the six ON runs wrote the same text,
    the same route meters and the same miss count (the timers vary), as
    docs/qwen36.md says they should. No ON arm without it was run, so that
    it would not reproduce without it is not shown here.
  - The LFRU swap count is 8.0 in both arms; the lever did not change how
    often the tier moved experts on this run length.
